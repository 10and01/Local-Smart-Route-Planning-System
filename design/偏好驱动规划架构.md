# 偏好驱动的路线规划架构（前置个性化设计）

## 一、核心思想：从"筛选路线"到"生成路线"

```
旧架构（事后打分）          新架构（偏好驱动）
  ┌──────────┐              ┌──────────┐
  │ 生成路线A │              │ 用户偏好  │
  │ 生成路线B │  ──×──→      │  ↓      │
  │ 生成路线C │   打分排序     │ 嵌入偏好  │
  └──────────┘              │  ↓      │
       ↓                    │ 规划过程  │
  哪条最匹配？               │  ↓      │
                            │ 直接生成  │
                            │ 最匹配路线 │
                            └──────────┘
```

**关键区别**：
- 旧架构：先生成候选 → 再比较谁更匹配用户 → 可能所有候选都不理想
- 新架构：用户偏好直接影响每一步决策 → 生成的路线天然匹配用户

## 二、四阶段偏好注入点

```
用户输入 + 偏好
     │
     ▼
┌────────────────────────────────────────────────────────────────┐
│ Stage 1: 偏好量化（Preference Quantization）                    │
│ ├─ 输出：用户偏好向量 UserPref = {美食:0.8, 拍照:0.9, 省钱:0.3...}│
│ └─ 作用：把自然语言偏好转换为可计算的权重                       │
└────────────────────────────────────────────────────────────────┘
     │
     ▼ 偏好注入点①：过滤候选集
┌────────────────────────────────────────────────────────────────┐
│ Stage 2: 偏好感知POI召回（Preference-Aware Recall）             │
│ ├─ 向量检索时，query = 用户意图 + 偏好加权                      │
│ ├─ 标签过滤时，优先保留高偏好匹配的POI类别                      │
│ └─ 输出：按"偏好匹配度"排序的候选POI列表                        │
└────────────────────────────────────────────────────────────────┘
     │
     ▼ 偏好注入点②：影响POI选择
┌────────────────────────────────────────────────────────────────┐
│ Stage 3: 偏好驱动路线构造（Preference-Driven Construction）     │
│ ├─ 贪心选择时：POI得分 = 基础分 × 偏好匹配系数                  │
│ ├─ 多目标权重：路程/体验/成本 的权重由用户偏好决定              │
│ ├─ 必去点处理：用户明确指定的必去点直接纳入约束                 │
│ └─ 输出：一条与用户偏好高度一致的初始路线                       │
└────────────────────────────────────────────────────────────────┘
     │
     ▼ 偏好注入点③：影响优化方向
┌────────────────────────────────────────────────────────────────┐
│ Stage 4: 偏好引导优化（Preference-Guided Optimization）         │
│ ├─ 2-opt交换时：不仅看路程，还看交换后偏好匹配度是否提升          │
│ ├─ 多套方案生成：不同偏好侧重 → 不同目标函数 → 不同路线         │
│ │   方案A（美食优先）：美食POI权重×2，允许绕路                  │
│ │   方案B（高效优先）：时间权重×2，牺牲部分体验                 │
│ │   方案C（深度优先）：高评分POI优先，数量少但质量高             │
│ └─ 输出：3条不同偏好侧重但各自最优的路线                        │
└────────────────────────────────────────────────────────────────┘
     │
     ▼ 偏好注入点④：解释内容生成
┌────────────────────────────────────────────────────────────────┐
│ Stage 5: 偏好对齐解释（Preference-Aligned Explanation）         │
│ ├─ 不是解释"这条路好"，而是解释"这条路为什么适合你"             │
│ ├─ 每个POI的推荐理由关联到用户的具体偏好词                      │
│ └─ 输出：个性化解释文案                                         │
└────────────────────────────────────────────────────────────────┘
```

## 三、关键技术实现

### 3.1 偏好量化模块

```python
class UserPreference:
    """用户偏好向量 - 贯穿整个规划流程的核心数据结构"""
    
    # 主题偏好 (0~1)
    theme_weights: Dict[str, float]  # {"美食": 0.9, "拍照": 0.8, "文化": 0.3}
    
    # 约束强度
    budget_level: str       # "经济" | "标准" | "高端"
    pace_preference: str    # "紧凑" | "适中" | "悠闲"
    
    # 行为偏好 (0~1)
    willingness_to_queue: float   # 是否愿意排队
    willingness_to_walk: float    # 是否愿意多走路
    price_sensitivity: float      # 价格敏感度
    
    # 人群标签
    traveler_type: str      # "独自" | "情侣" | "亲子" | "朋友" | "家庭"
    
    # 生成的动态权重（用于规划算法）
    @property
    def poi_score_weights(self) -> Dict[str, float]:
        """
        将用户偏好转换为POI评分的多目标权重
        直接影响贪心选择时的POI得分计算
        """
        return {
            "experience": 0.3 + max(self.theme_weights.values()) * 0.4,
            "time_efficiency": 0.3 if self.pace_preference == "紧凑" else 0.15,
            "cost": 0.2 if self.price_sensitivity > 0.5 else 0.1,
            "preference_match": 0.3 + sum(self.theme_weights.values()) * 0.1,
        }
```

### 3.2 偏好注入规划引擎（核心算法）

```python
def preference_driven_route_plan(
    candidates: List[POI],
    user_pref: UserPreference,
    constraints: RouteConstraints
) -> RoutePlan:
    """
    偏好驱动的路线规划 - 个性化内嵌在每一步决策中
    """
    
    # === 步骤1: 基于偏好的POI预筛选和排序 ===
    scored_candidates = []
    for poi in candidates:
        # 计算POI与用户的偏好匹配度（0~1）
        preference_match = compute_preference_match(poi, user_pref)
        
        # 计算人群适配度（情侣/亲子/独自）
        crowd_match = compute_crowd_match(poi, user_pref.traveler_type)
        
        # 综合预评分 = 基础质量 × 偏好匹配 × 人群适配
        pre_score = (
            (poi.rating / 5.0) * 0.3 +
            preference_match * 0.5 +
            crowd_match * 0.2
        )
        
        scored_candidates.append((poi, pre_score, preference_match))
    
    # 按预评分排序 - 高偏好匹配的POI优先被考虑
    scored_candidates.sort(key=lambda x: x[1], reverse=True)
    
    # === 步骤2: 基于偏好的贪心路线构造 ===
    route = Route()
    remaining = [item[0] for item in scored_candidates]
    current_time = constraints.start_time
    current_location = constraints.start_point
    
    # 优先处理必去点
    for must in constraints.must_visit:
        if must in remaining:
            # ... 插入必去点逻辑
            pass
    
    while remaining and current_time < constraints.end_time:
        best_poi = None
        best_marginal_value = -float('inf')
        
        for poi in remaining:
            travel_time = estimate_travel(current_location, poi.location)
            arrive_time = current_time + travel_time
            
            # 时间窗检查
            if not is_open(poi, arrive_time):
                continue
            
            # 预算检查
            if poi.price and constraints.budget:
                spent = sum(p.price for p in route.pois if p.price)
                if spent + poi.price > constraints.budget:
                    continue
            
            # ========== 核心：偏好驱动的POI得分 ==========
            base_score = poi.rating / 5.0  # 基础质量
            
            # 获取该POI的偏好匹配度（预计算）
            pref_match = next(
                (item[2] for item in scored_candidates if item[0] == poi), 0
            )
            
            # 根据用户偏好计算多维度得分
            weights = user_pref.poi_score_weights
            
            poi_value = (
                weights["experience"] * base_score +
                weights["preference_match"] * pref_match +
                weights["cost"] * (1 - poi.price / max(1, constraints.budget or 500))
            )
            
            # 时间效率惩罚（用户偏好决定惩罚强度）
            time_penalty = travel_time * (0.5 if user_pref.pace_preference == "悠闲" else 1.0)
            
            # 边际价值 = POI价值 - 交通成本
            marginal_value = poi_value * 100 - time_penalty
            
            # 额外：如果用户愿意排队且该POI很热门，额外加分
            if user_pref.willingness_to_queue > 0.6 and poi.popularity > 0.8:
                marginal_value += 20
            
            # 额外：如果用户是情侣且该POI是浪漫标签，额外加分
            if user_pref.traveler_type == "情侣" and "浪漫" in poi.tags:
                marginal_value += 25
            
            if marginal_value > best_marginal_value:
                best_marginal_value = marginal_value
                best_poi = poi
        
        if best_poi is None:
            break
        
        # 插入选中的POI
        route.add_poi(best_poi, current_time)
        current_time += estimate_travel(current_location, best_poi.location)
        current_time += best_poi.suggested_duration
        current_location = best_poi.location
        remaining.remove(best_poi)
    
    # === 步骤3: 偏好引导的2-opt优化 ===
    route = preference_guided_two_opt(route, user_pref)
    
    return route
```

### 3.3 偏好引导的2-opt优化

```python
def preference_guided_two_opt(route: Route, user_pref: UserPreference) -> Route:
    """
    标准的2-opt只优化路程，这里同时优化偏好匹配度
    """
    improved = True
    while improved:
        improved = False
        for i in range(1, len(route.pois) - 1):
            for j in range(i + 1, len(route.pois)):
                # 标准2-opt：计算路程变化
                old_distance = (
                    route.distance_between(i-1, i) +
                    route.distance_between(j, j+1 if j+1 < len(route.pois) else 0)
                )
                new_distance = (
                    route.distance_between(i-1, j) +
                    route.distance_between(i, j+1 if j+1 < len(route.pois) else 0)
                )
                distance_delta = new_distance - old_distance
                
                # 新增：计算偏好匹配度变化
                old_preference_score = compute_route_preference_score(
                    route, user_pref, i, j
                )
                # 模拟交换后的偏好得分
                route.reverse_segment(i, j)
                new_preference_score = compute_route_preference_score(
                    route, user_pref, i, j
                )
                route.reverse_segment(i, j)  # 恢复
                
                preference_delta = new_preference_score - old_preference_score
                
                # 综合判断是否交换
                # 用户偏悠闲 → 允许轻微绕路换取更高偏好匹配
                # 用户偏紧凑 → 优先路程最短
                distance_weight = 1.0 if user_pref.pace_preference == "紧凑" else 0.6
                preference_weight = 0.5 if user_pref.pace_preference == "紧凑" else 1.0
                
                total_delta = (
                    distance_weight * distance_delta +
                    preference_weight * (-preference_delta * 1000)  # 转换为同量纲
                )
                
                if total_delta < 0:  # 交换后更优
                    route.reverse_segment(i, j)
                    improved = True
    
    return route
```

### 3.4 多方案生成（不同偏好侧重）

```python
def generate_preference_variants(
    candidates: List[POI],
    base_pref: UserPreference,
    constraints: RouteConstraints
) -> List[RoutePlan]:
    """
    基于同一用户偏好，生成3个不同侧重的方案
    每个方案通过调整权重来侧重不同维度
    """
    variants = []
    
    # 方案A：体验优先（侧重偏好匹配 + 高评分）
    pref_a = copy.deepcopy(base_pref)
    pref_a.theme_weights = {k: v * 1.5 for k, v in pref_a.theme_weights.items()}
    route_a = preference_driven_route_plan(candidates, pref_a, constraints)
    route_a.theme = "深度体验"
    route_a.description = f"专注你最感兴趣的{top_theme(pref_a)}，精选高匹配度POI"
    variants.append(route_a)
    
    # 方案B：效率优先（侧重时间 + 路程）
    pref_b = copy.deepcopy(base_pref)
    pref_b.pace_preference = "紧凑"
    pref_b.willingness_to_walk = 0.2
    route_b = preference_driven_route_plan(candidates, pref_b, constraints)
    route_b.theme = "高效省时"
    route_b.description = "在最短时间内打卡最多亮点，适合时间紧张"
    variants.append(route_b)
    
    # 方案C：均衡方案（原始偏好权重）
    route_c = preference_driven_route_plan(candidates, base_pref, constraints)
    route_c.theme = "均衡推荐"
    route_c.description = "兼顾体验、时间和预算的综合最优方案"
    variants.append(route_c)
    
    return variants
```

## 四、架构对比：后置 vs 前置个性化

| 维度 | 后置个性化（旧） | 前置个性化（新） |
|------|----------------|----------------|
| **路线匹配度** | 可能所有候选都不理想 | 生成的路线天然匹配用户 |
| **必去点处理** | 生成后检查是否包含 | 构造阶段强制优先插入 |
| **多方案差异** | 细微差异，本质相似 | 根本不同的优化方向 |
| **解释自然度** | "这条路适合你"（牵强） | "因为你喜欢X，所以先去Y"（顺理成章） |
| **计算复杂度** | 生成N条 × 打分 = N次规划 | 1次规划（偏好内嵌）+ 2次变体 = 3次 |
| **可解释性** | 事后找理由 | 每个决策都有偏好依据 |

## 五、解释生成的升级

### 旧版解释（事后生成）

### 新版解释（偏好对齐）
> "知道你**喜欢拍照和浪漫氛围**，所以把『断桥残雪』安排在上午——光线最柔和，游人还不多。接着去『% Arabica』，落地窗前就是西湖景，**出片率超高**。下午登雷峰塔俯瞰西湖全景，**情侣合照绝佳点位**。」

```python
def generate_aligned_explanation(route: RoutePlan, user_pref: UserPreference) -> str:
    segments = []
    
    for i, poi in enumerate(route.pois):
        # 找到这个POI匹配了用户的哪些偏好
        matched_prefs = []
        for theme, weight in user_pref.theme_weights.items():
            if weight > 0.5 and theme in poi.tags:
                matched_prefs.append(theme)
        
        # 找到时间安排的合理性
        time_reason = ""
        if i == 0 and "拍照" in matched_prefs:
            time_reason = "光线最好"
        elif poi.category == "餐饮" and route.arrive_times[i].hour == 12:
            time_reason = "正好饭点"
        
        # 组装该POI的推荐理由
        if matched_prefs:
            reason = f"因为你想{'和'.join(matched_prefs)}，{poi.name}{'（' + time_reason + '）' if time_reason else ''}"
            segments.append(reason)
    
    # 用LLM润色
    prompt = f"""
    用户偏好：{user_pref.theme_weights}
    出行人群：{user_pref.traveler_type}
    
    以下是被选中的POI及其匹配原因：
    {'\n'.join(segments)}
    
    请用第二人称写一段自然的路线推荐理由，突出"为什么适合你"，
    每个POI都要关联到用户的具体偏好，100字左右。
    """
    return llm_generate(prompt)
```

## 六、一句话总结

> **把"先规划再筛选"改为"让偏好引导规划"，每个POI的选择、排序、取舍都有用户的偏好作为决策依据，生成的路线不是"被选中"的，而是"被设计出来"的。**
